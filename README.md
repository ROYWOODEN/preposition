# Predlog — Telegram-предложка

Локальный бот на TypeScript с SQLite. Пользователь составляет публикацию, просматривает результат и отправляет на модерацию. Модераторы работают в личных сообщениях бота. Владелец управляет доступом, шаблонами и настройками.

## Согласованное поведение

- Один публичный канал; бот доступен только его подписчикам. Перед обработкой каждого обращения проверяется членство через Telegram, включая повторную проверку при отправке на модерацию. Если API не отвечает, доступ не разрешается до успешной проверки.
- Одна заявка публикуется текстовым сообщением, одним вложением с подписью или альбомом фото/видео. Длинный текст не делится автоматически.
- Максимум 4096 UTF-16 единиц для текста, 1024 для подписи, включая подпись автора; проверка намеренно консервативная для emoji.
- До 10 совместимых фото/видео; документы, анимация, аудио и голосовые — по одному на заявку. Стикеры, опросы и видеокружки не поддерживаются.
- Новый пост сохраняется в отдельный черновик. После сохранения следующее самостоятельное сообщение создаёт новый пост. Для дополнения существующего выберите «Добавить медиа» или «Редактировать текст». Форматирование Telegram сохраняется.
- До 20 отдельных черновиков на пользователя; по умолчанию 10 ожидающих заявок и 60 секунд между отправками. Черновики не удаляются автоматически.
- Автор может менять текст ожидающей заявки. Модераторы могут править текст, но не заменять медиа.
- Анонимность скрывает автора от читателей канала, но не от модераторов.
- Отклонение требует готовой или собственной причины, видимой автору.

## Установка и запуск на Windows

Проверено локально с Node.js 26.13.1 и npm 11.20.0. Зависимости закреплены в package-lock.json. Используется npm, установка глобального TypeScript и отдельного сервера SQLite не нужна.

```powershell
npm.cmd ci
Copy-Item .env.example .env
```

Заполните `.env` в редакторе. Не отправляйте токен в чат, не помещайте его в команды терминала или Git.

| Переменная        | Значение                                            |
| ----------------- | --------------------------------------------------- |
| BOT_TOKEN         | Токен вашего бота из @BotFather                     |
| OWNER_TELEGRAM_ID | Числовой ID владельца                               |
| TARGET_CHANNEL_ID | Числовой ID канала вида -100…                       |
| DATABASE_PATH     | Путь к файлу SQLite, по умолчанию ./data/bot.sqlite |
| LOG_LEVEL         | info, debug, warn, error и другие уровни Pino       |

Для нового бота: `/newbot` в @BotFather. В канале добавьте бота администратором с правом публикации. Для личных уведомлений будущий модератор должен открыть бота и нажать стандартную кнопку Telegram «Начать». Удобнее сделать это через приглашение владельца.

Чтобы определить ID, сначала впишите BOT_TOKEN, отправьте боту `/start`, остановите другие экземпляры бота и выполните:

```powershell
npm.cmd run diagnose -- @username_вашего_канала
```

Скрипт показывает ID канала, права бота и ID пользователей из доступных обновлений, не выводит токен или сообщения и ничего не публикует. Если пользователей несколько, поочерёдно сопоставьте собственное новое обращение. После настройки основной бот также поддерживает `/id`.

```powershell
npm.cmd run db:migrate
npm.cmd run dev
```

Первый запуск миграций создаёт базу и таблицы. Повторный запуск применяет только новые миграции. Приложение само не меняет схему при старте. При некорректном окружении запуск прекращается.

## Работа с ботом

Весь основной сценарий доступен через кнопки. «Предложить пост» создаёт новый черновик; «Черновики» возвращает к сохранённым постам; «Мои заявки» показывает отправленные заявки. Номера для автора личные, для модерации — общие. На странице до 10 записей; кнопка показывает дату и начало текста. Для опубликованного поста используется дата публикации, до неё — отправки или создания; часовой пояс — Москва.

Основная клавиатура занимает до трёх строк. Инструменты владельца и модератора собраны в «Управление»; клавиатура не закреплена принудительно. «Скрыть меню» убирает её и оставляет кнопку возвращения. В черновиках доступна очистка с подтверждением: она отменяет только черновики текущего пользователя, не удаляет историю и не затрагивает заявки на рассмотрении. Очищенные черновики скрываются из пользовательских списков.

В пустом черновике есть только навигация. После добавления содержимого появляются предпросмотр, редактирование и добавление медиа. Части одного альбома привязаны к исходному черновику, даже если человек уже открыл другой. Отдельный новый текст не перезаписывает сохранённый пост. Команды остаются дополнительными сокращениями и не требуются для работы.

Для альбома дождитесь загрузки всех файлов и проверьте количество в предпросмотре. После последнего изменения действует пауза 2 секунды. Новое вложение меняет версию и делает прежнее подтверждение недействительным. У Telegram нет сигнала о полном завершении доставки альбома: окончательная проверка предпросмотра остаётся важной. Позднее вложение после отправки отклоняется явно, а не добавляется молча к одобренному посту.

Модератор открывает «Модерация» или кнопку в уведомлении, просматривает публикацию и принимает решение. Устаревшее одобрение после правки текста не сработает. «История» показывает действия на русском с датами и переходом к посту; владелец видит общую историю. В модераторской карточке всегда виден автор со ссылкой на профиль и отдельно отмечено желание публиковаться анонимно. Менять анонимность может только автор в своей карточке.

Владелец добавляет модераторов по @username или ссылке t.me/username среди известных боту пользователей. Перед назначением профиль проверяется по стабильному Telegram ID и показывается для подтверждения. Telegram Bot API не поддерживает поиск произвольного личного профиля по username: для неизвестного пользователя доступна кнопка «Пригласить по ссылке». Одноразовая ссылка действует 24 часа. После перехода человека владелец получает профиль кандидата и отдельно подтверждает назначение. Пересланное приглашение само по себе не выдаёт права.

В разделе добавления также есть «Выбрать в Telegram»: встроенное окно выбора передаёт ID под капотом. Профиль проверяется через личный чат или членство в канале, затем владелец подтверждает назначение. Для отсутствующего в базе @username используйте этот путь либо «Получить приглашение». Приглашение — ссылка на бота, а не ссылка на профиль человека.

В списке модераторов отображаются имена и ссылки, сведения обновляются по ID, когда Telegram предоставляет доступ. При недоступности API остаётся сохранённое имя и ссылка по ID; привязка прав к username не используется. Владелец не может удалить собственные права.

Настройки содержат пояснения и русские названия. «Сообщения бота» и «Причины отклонения» — отдельные разделы. Доступны просмотр, редактирование и сброс шаблонов. Для уведомлений используются только разрешённые плейсхолдеры; `{submission_id}` означает личный номер заявки автора; JavaScript не исполняется. Существующие пользовательские шаблоны не перезаписываются.

Можно добавить до 20 собственных причин отклонения, изменить или удалить любую причину. Даже при пустом списке модератор может написать собственный ответ. «Сбросить настройки» после отдельного подтверждения восстанавливает переключатели, лимиты, стандартные сообщения и причины; посты, роли, блокировки и история не меняются.

## Ошибки отправки

Решение `approved` отдельно от доставки `publishing/published/failed/needs_review`. Повторная кнопка не отправляет пост второй раз. При неопределённом результате сети или перезапуске во время отправки автоматического повтора нет.

Владелец открывает «Проверка публикаций», вручную проверяет канал и отмечает публикацию как состоявшуюся либо возвращает заявку на модерацию **только если пост отсутствует**. Для `failed` сначала исправьте права/сеть/ограничения Telegram. Затем новое одобрение запускает новую попытку.

Уведомления хранятся в SQLite и отправляются непосредственно после отправки заявки или решения модератора. Десятисекундный таймер служит только для восстановления и отложенных повторов. Уведомления содержат кнопку перехода к посту. При 429 учитывается retry_after, максимум 5 попыток. Неопределённый результат уведомления сохраняется для проверки, без слепого повтора. Блокировка бота получателем не отменяет опубликованный пост.

Один экземпляр на файл базы. Lock-файл защищает запуск; после аварии проверяется PID. Не удаляйте lock-файл при работающем боте. Запускайте команды из корня проекта.

## Проверки

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run test:run
npm.cmd run build
npm.cmd run start
```

`test` запускает наблюдение Vitest; `format` — Prettier. Тесты используют отдельную SQLite в памяти и подменённый HTTP-транспорт Telegram. Они не публикуют сообщения.

Ручная проверка на основном канале (по согласованию владельца): сначала проверьте меню, ID, роли, черновики, исправления и отклонения без публикации. Затем отправьте явно помеченный тестовый текст, фото, видео, альбом, документ, анимацию, аудио и голосовое. Проверяйте предпросмотр, подпись, анонимность, уведомления, повторную кнопку, отмену, удаление модератора и сохранность после перезапуска. Тестовые посты видны подписчикам; удаляйте их вручную при необходимости.

## База и резервные копии

Drizzle ORM, SQLite WAL, foreign_keys=ON, busy_timeout=5000. Миграции версионируются в `migrations/`. `db:generate` создаёт новую миграцию из схемы; перед применением проверьте SQL. Не заменяйте миграции командой push.

```powershell
npm.cmd run db:backup
```

Используется SQLite online backup API, учитывающий WAL. Нельзя просто копировать один файл работающей WAL-базы. Копии содержат персональные данные: храните их с ограниченным доступом отдельно от сервера.

Восстановление: остановите бота; сохраните резервную копию текущей базы; переместите текущую базу и её файлы `-wal`/`-shm` в архив; положите проверенную резервную копию по DATABASE_PATH; выполните миграции подходящей версии и запустите бота. Не подмешивайте WAL от старой базы. Проверьте историю и заявки после восстановления.

## Перенос на хостинг

Подходит VPS или сервис с постоянным Node.js-процессом и постоянным диском. Нужен один экземпляр; Docker и веб-сервер не используются. Long polling требует только исходящего доступа к Telegram. Пока выбор и установка сервиса запуска отложены до ручного тестирования.

На сервере: установите совместимый Node.js, перенесите исходники и lock-файл, выполните `npm ci`, тесты и сборку. Отдельно создайте `.env`, перенесите согласованную резервную копию базы, примените миграции. Остановите локального бота перед запуском серверного. Рабочая команда — `node --env-file=.env dist/main.js`. Настройку systemd обсудим при выборе VPS.

Обновление: резервная копия, остановка, новые исходники, `npm ci`, проверки, сборка, миграции, запуск. Откат схемы не автоматический: используйте совместимую версию и резервную копию.

## Диагностика

- 401: неверный токен — замените локально; при утечке перевыпустите в BotFather.
- 403 при публикации: проверьте ID канала и право публикации.
- 409 polling: запущен второй экземпляр либо настроен webhook. Остановите второй экземпляр; удаление webhook выполняйте осознанно.
- `no such table`: выполните db:migrate из корня проекта.
- Нативная SQLite не загружается: повторите npm ci на совместимой версии Node.js, проверьте доступность готового бинарного пакета.
- npm не найден/нельзя выполнить npm.ps1: используйте npm.cmd.
- Проверка конфигурации сообщает только имена неверных переменных, не их значения. Тела Telegram-ошибок и токены в логи не выводятся.

При запуске проверяется совместимость схемы. Если приложение сообщает, что база требует обновления, выполните `npm run db:backup`, затем `npm run db:migrate` перед новым запуском. Для обновления интерфейса добавлена миграция 0002: кнопки уведомлений и приглашения модераторов. Без неё бот теперь не начнёт работу с частично доступными функциями.

Структурированные логи записываются в `bot.log` рядом с базой и в консоль. При ошибке фиксируются номер обновления, тип ошибки и код SQLite/Telegram, без текста сообщений и токена. `npx tsx scripts/check-access.ts` проверяет только чтением схему, права и доступность известных профилей; выводит агрегированные результаты без персональных данных.

Реальное Telegram-тестирование требует заполненного .env. Успешные автоматические тесты не заменяют эту проверку.
